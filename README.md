# TVHelper · TradingView 助手

<img src="assets/icon.png" width="88" alt="TVHelper icon" />

本地运行的 TradingView 桌面版多账号管理器：每个账号一份独立配置目录，可同时在线、互不串号。所有改动只作用于本地副本，不动已安装的 TradingView。

## 功能

界面上的开关，拨动即生效：

- 拦截广告弹窗
- 多图表布局解锁
- 指标叠加解锁
- 绘图不限
- 断线自动恢复
- 禁用自动更新
- 本地指标报警

## 本地指标报警

免费版只能建价格报警。这条功能补上**指标报警**——用图表上的任意指标建，条数不限，不占服务端配额。

- 入口：绘图工具栏「警报」按钮下方的蓝色铃铛、右下角「报警 N」，或快捷键 `Alt+A`
- 条件取自指标自己声明的条件名（与原生对话框一致），没有条件名时用它的输出值和图形信号
- 列表与原生警报面板同一套样式，一行一条，点开可看详情、改设置、删除
- 消息标题与内容可自定义，支持 `{{ticker}}` `{{close}}` 等占位符
- 通知方式：系统通知，或用你自己的邮箱发信（SMTP，465 SSL 或 587 STARTTLS，填账号与授权码）
- 配置保存在账号目录的 `tvx-alerts.json`，重启后自动恢复

限制：

- 软件关掉就不监控
- 图表没打开、品种或周期不匹配、指标被删掉时，该条报警显示「未就绪」，不会误触发
- 行情本身有延迟（免费账号部分市场延迟 15 分钟），报警跟着行情走
- 服务端报警（邮件/短信/webhook，关机也运行）仍然需要订阅

## 绘图不限

免费版每张图表最多 30 个绘图（趋势线、水平位、斐波那契、矩形……都算），超了点了没反应，还弹升级框。打开这条开关这个限制就没了。

- 按单张图表计数，所有 pane 合计；同一种工具画 10 次算 10 个
- 隐藏或锁定的绘图照样占额度，删除立即释放；指标、脚本、报警不计入
- 超额画出来的绘图会正常保存，重开图表还在
- 以后升级到付费方案也不用关，没有副作用

## 拦截广告弹窗

广告和充值提示合成一个开关：广告域名不进网络，订阅/升级窗口不打开，图表里的推广浮层也不显示。

- 启动时可能弹出的订阅遮罩、图表页内的升级浮层、以及网页请求打开充值页面的链接，都不再出现
- 真断线的提示不在此列，那是「断线自动恢复」负责的
- 顶栏常驻的升级小按钮不在处理范围内

## 功能没生效？按这个顺序看

先看助手的顶栏标签：

| 标签 | 含义 | 你该做什么 |
|---|---|---|
| `● 副本 3.5.x · 补丁完好` | 万事俱备 | 若功能仍无反应，多半是启动的不是副本 —— 见下面第 3 条 |
| `● 副本 3.5.x · 旧包未清除`（红） | 副本里还留着原始包，客户端会优先加载它，**补丁一条都不执行** | 先点「全部停止」，然后拨动任意开关（会自动清掉它），再「全部启动」 |
| `● 副本 3.5.x · 补丁异常`（黄） | 有个别补丁没对上 | 点「生成 / 更新副本」；日志里 `[!] 功能名` 就是没生效的那条 |
| `● 副本未生成` | 还没建副本 | 点「生成 / 更新副本」 |

还没解决，按这四条查：

1. **客户端没关就重建** —— 副本里的程序会被占用，构建会中止。先「全部停止」，再「生成 / 更新副本」。
2. **杀软拦了文件操作** —— 典型表现是重建时删不掉旧包。把 `%USERPROFILE%\.tvx` 加进杀软白名单后重试。
3. **启动的不是副本** —— 快捷方式、任务栏、开始菜单如果指向系统里安装的 TradingView，补丁自然不会生效。从助手界面启动，或者直接确认任务管理器里 `TradingView.exe` 的路径是 `C:\Users\<你>\.tvx\apps\...`。
4. **改完没重启客户端** —— 补丁在启动时加载，改开关后必须重启才能生效。

报警按钮不出现时，图表右侧会有一个红色「报警不可用」小标，鼠标停上去会说明原因和处理方式。

界面右上「自检」会生成完整报告（也写到 `~/.tvx/doctor.txt`），反馈问题时把它一起发来最省事。

## 构建

需要 Rust stable。

```bash
cargo build --release
# 产物：target/release/tvhelper(.exe)，Windows 另需 MSVC 工具链
```

命令行维护入口（release 版没有控制台，出问题先用它们把结论打出来）：

| 命令 | 作用 |
|---|---|
| `tvhelper _version` | 版本 + 自身路径 + 文件大小，并写 `~/.tvx/version.txt` |
| `tvhelper _doctor` | 环境自检与副本补丁清单，报告写 `~/.tvx/doctor.txt` |
| `tvhelper _reapply` | 按当前开关重打托管副本的补丁（不开界面） |
| `tvhelper _build` | 从系统安装构建 / 重建托管副本 |

## 代码结构

```
src/
  main.rs         入口：解析命令行 → 无头命令 → 否则开界面
  cli.rs          子命令定义与参数解析（纯函数，有测试）
  app.rs          界面主体：App 状态、后台结果消费、update() 骨架
  app/state.rs    Shared / 盘点线程 / 一次性任务
  app/authwatch.rs 发现新登录页 → 决定要不要自动打开（三道防死循环闸）
  app/actions.rs  Act 的执行（启动、停止、重建、开关重打…）
  app/headless.rs _reapply / _build / 打开目录
  app/theme.rs    字体栈、样式、状态色
  app/view.rs     一帧的只读快照 + 日志区；面板在 view/head.rs、view/accounts.rs
  install.rs      配置、托管副本、路径与原子写
  install/health.rs   环境体检 + 自检报告
  install/discover.rs 发现已安装的客户端
  install/build.rs    复制 → 解包 asar → 打补丁 → macOS 重签名
  patch.rs        补丁引擎：匹配、通配锚点、按段迁移、资源落盘
  patch/data.rs   版本白名单 + 注入脚本 + 补丁表（换版本只改这里）
  profiles.rs     多账号档案 CRUD
  profiles/account.rs 账号身份识别（JWT / 本地存储）
  profiles/auth.rs    深链回调、应用内登录页、回调接管
  profiles/runtime.rs PID 文件、存活判定、启动停止
  i18n.rs         文案结构 + 按语言取词的助手方法；zh.rs / en.rs 是文案表
  alerts/0*.js    页内报警引擎（build.rs 按序拼成一份再嵌入）
  alerts-main.js  主进程侧：IPC、配置持久化、系统通知、SMTP
```

两条不变量：

- **补丁数据与匹配算法分离**。换客户端版本只改 `patch/data.rs`，`patch.rs` 里的通配锚点与迁移逻辑不动。
- **界面不直接做系统调用**。面板只读快照、只产出 `Act`；副作用集中在 `app/actions.rs` 与后台线程。
